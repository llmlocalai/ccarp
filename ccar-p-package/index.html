4. Ten judgment rules tie-breakers

When two options both look right, one of these usually settles it.

#RuleWhere
1Remove > prevent > instruct > detect. Remove the capability if you can; else a deterministic preventive control (hook, schema, DB permission, authz); only then instruction; logging/review last. (Enforcement ladder — Sample Q1.)M1,M2,M3
2Solve the risk the stem names. Distractors solve a real but different risk.all
3Lightest solution that solves the problem. Fewest primitives, zero-shot first, workflow before agent, default Sonnet, MCP only when reused.M1
4Governance first. Compliance, procurement, data residency exclude options before cost, latency, convenience.M1,M2,M4
5Rules/real-time facts/computation → code or systems. Language work → Claude. High-stakes decisions → a human.M1
6Stable knowledge → retrieval. Live state → tools. Using RAG instead of a tool call is the most common mistake.M1
7Every change is an eval-gated release, with the threshold set before the run (model swap, prompt edit, context change).M1,M2
8Look at distributions and segments, not averages. Token distribution, p95 latency, eval score by segment.M2
9Structure beats sentences. Output contract, schema, hook, authorization > a rule written into the prompt.M1,M3
10Prevention beats detection. Ask: does this stop the bad output, or only help me find it afterward?M1,M3

Common distractor patterns / 常见干扰项模式

  • More context always improves quality.
  • The largest model is always safest.
  • A prompt instruction, a CLAUDE.md line, or a Skill is an enforceable guardrail.
  • Logging or a confirmation prompt equals least privilege.
  • MCP is always better than calling the API directly.
  • When multi-agent breaks, rerun the whole pipeline or add more logging.
  • Average latency or average accuracy met the SLA.
  • The vendor already ran a bias evaluation, so fairness is handled.
  • When the stem signals latency or a configuration problem, "none required" is the safe answer.

5. Four model properties foundation of everything else

PropertyGood atBad atDesign response
Next-token prediction / non-determinismPattern-rich language work: summarize, rewrite, explain, draftExact details: names, dates, citations, statistics; same input, different outputEval. One clean demo is not evidence. Verification loops, citations, facts go to tools
Knowledge boundaryCommon, stable, well-documented topicsRare, private, recent, fast-changing facts — stated confidently anywayRetrieval and tools. External systems are the source of truth
Working memory (finite context)Anything inside the context windowThe window edge is a cliff; quality degrades before the hard limitContext strategy is a design decision: progressive loading, chunking, compaction
Steerability / confidence ≠ correctnessShort, specific, verifiable, formatted instructionsVague goals, long reasoning chains, precise arithmetic — wrong answers delivered just as confidentlyHITL placement and verification. Schema, code execution, review where errors cost most

Mnemonic: Unpredictable → test it. Doesn't know → go retrieve it. Doesn't fit → make a choice. Can't tell right from wrong → go verify.

不可预测 → 测试它。不知道 → 去取。装不下 → 做选择。分不清对错 → 去核查。判定规则：针对根本原因，而不是症状。
